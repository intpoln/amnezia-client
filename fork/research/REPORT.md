# Улучшенный форк AmneziaVPN: что можно сделать и насколько это сложно

Дата: 2026-10-30. Изучалась ветка `dev` upstream (версия 5.1.0.5, коммит `7f9b7db`), клон лежит в `CustomAmnezia/amnezia-client`.

Источники:
- 4 субагента Claude: Windows и служба, Android, другие VPN-клиенты, разбор 1554 issues и 1500 PR на GitHub;
- независимый разбор Codex (GPT-6-Astra, medium), полный текст в [codex_report.md](codex_report.md);
- ключевые находки я перепроверил по коду сам, они помечены ✅.

---

## 1. Коротко

1. **Форк делать имеет смысл.** VPN-ядро переписывать не нужно. Почти все ваши жалобы лежат в обвязке вокруг протоколов: интерфейсе, службе Windows и Android-части.
2. **Папки вместо .exe возможны.** Драйвер менять не придётся: клиент сам находит все .exe в папке и передаёт их драйверу списком.
3. **У «тормозов» есть конкретные причины в коде**, и часть из них исправляется за часы. Самая яркая: при каждом подключении служба выполняет `netsh int ip reset` и `netsh winsock reset` ✅.
4. **Upstream почти не принимает чужие исправления.** В 2026 году закрыто 12% issues, висят 189 открытых PR. Многие хорошие исправления от сообщества уже написаны, их можно просто забрать к себе.
5. **Самое трудное:** режим «только выбранные приложения через VPN» на Windows для AmneziaWG. Нынешний драйвер Mullvad умеет только исключать приложения. Для протокола Xray такой режим сделать проще.

## 2. Как устроен клиент (простыми словами)

```
Окно (Qt/QML) ──► логика (C++) ──► поток подключения (VpnConnection)
                                        │
             Windows: служба с правами администратора (AmneziaVPN-service)
                      ├─ протоколы AmneziaWG/WireGuard (отдельная Windows-служба туннеля)
                      ├─ OpenVPN, Xray (через tun2socks)
                      ├─ маршруты, DNS, kill switch (фильтры WFP)
                      └─ драйвер раздельного туннелирования mullvad-split-tunnel.sys
             Android: VpnService на Kotlin, по отдельному процессу на каждый протокол
```

- Окно и служба на Windows общаются по **двум** каналам. Первый: Qt Remote Objects (маршруты, DNS, Xray, OpenVPN). Второй: JSON по named pipe `\\.\pipe\amneziavpn` (AmneziaWG/WireGuard, код взят из Mozilla VPN).
- **Вся служба однопоточная.** Если одна операция зависла, например `netsh` или драйвер, ждут все остальные.
- Сборка: C++/Qt 6.10, CMake, Conan, MSVC 2022. Для Android ещё Gradle и NDK. Готовые бинарники зависимостей подтягиваются с сервера Amnezia, поэтому собирать протоколы из исходников обычно не нужно.

## 3. Раздельное туннелирование приложений на Windows

### Как работает сейчас ✅
- Кнопка «+» открывает обычный диалог выбора **одного** файла ([PageSettingsAppSplitTunneling.qml:224](../../client/ui/qml/Pages2/PageSettingsAppSplitTunneling.qml)).
- Список хранится в реестре, в HKCU, как JSON с путями.
- При подключении список уходит в службу. Служба переводит пути в формат `\Device\HarddiskVolumeN\...` и передаёт их драйверу Mullvad ([windowssplittunnel.cpp:293](../../client/platforms/windows/daemon/windowssplittunnel.cpp)).
- Драйвер сравнивает **полный путь к .exe**. Папок, масок и регулярных выражений в его протоколе нет.
- Драйвер **умеет только исключать** приложения из VPN.
- Драйвер **передаёт исключение дочерним процессам.** Если исключить лаунчер (Steam, Epic, лаунчер игры), исключаются и запущенные им игры. Уже сейчас это частично решает проблему «много .exe».
- Исключение работает для AmneziaWG, WireGuard, OpenVPN и Xray. Для IKEv2 не работает.
- Пока VPN подключён, страница настроек заблокирована.
- В списке показывается только имя файла без папки. Два `game.exe` из разных мест выглядят одинаково.

### Добавление папок: варианты

| Вариант | Что получится | Сложность |
|---|---|---|
| **0. Мелочи** | Выбор нескольких .exe за раз, полный путь в списке, фильтр `*.exe` | Лёгкая, часы |
| **A. Правило «папка»** | В списке одна строка «D:\Games\Foo (12 exe)». При каждом подключении клиент в фоне заново обходит папку и подпапки. Новые exe после обновления игры подхватятся при следующем подключении. Службу и драйвер менять не нужно. | Средняя, 1–3 дня |
| **B. Выбор из запущенных процессов** | Список процессов с иконками и поиском, группировка по папкам, кнопка «добавить всё из этой папки» | Лёгкая–средняя, около 1–2 дней |
| **C. Выбор из установленных программ и игр** | Ярлыки из меню «Пуск», ключи Uninstall в реестре, библиотеки Steam (`libraryfolders.vdf`) и Epic (manifests). Каждая программа добавляется как правило-папка из варианта A. | Средняя, 2–4 дня |
| **D. Применение на лету** | Отслеживание изменений в папке и правка списка без переподключения. Требует нового IPC-метода в службе. Заодно можно разрешить менять список при включённом VPN. | Средняя–высокая, около недели |
| **E. Папки внутри драйвера** | Форк драйвера Mullvad. Изменённый драйвер нужно подписывать у Microsoft (EV-сертификат). Альтернатива, test-signing, ломает античиты. | Очень высокая, **не рекомендую** |

**Рекомендация: 0 → A → B → C**, а D делать, только если всё ещё будет мешать.

Ограничения, которые останутся при любом варианте:
- приложение, запущенное до подключения VPN, нужно перезапустить;
- DNS-запросы исключённых приложений всё равно идут через системную службу `dnscache`, то есть через туннель;
- приложения из Microsoft Store и игры с некоторыми античитами (Valorant, LoL) исключаются плохо или не исключаются вовсе.

### Режим «только выбранные приложения через VPN» на Windows
Это самый частый запрос в issues (#1127 и другие). Upstream, похоже, над ним работает: открыт PR сотрудника #3152 и есть community PR #2598, которому нужен изменённый драйвер.
- **Для Xray/VLESS сделать реально.** У Xray есть свои правила маршрутизации по процессу, и они **поддерживают папки** (путь с `/` на конце). Сложность средняя–высокая.
- **Для AmneziaWG нужен другой драйвер** или пропуск всего трафика через userspace-TUN с правилами по процессам, как в sing-box или mihomo. Это очень трудно. Лучше подождать upstream и забрать у них.

## 4. Почему клиент «подглючивает» (Windows)

Отсортировано по вероятному вкладу.

| # | Проблема | Где | Исправление | Сложность |

Это сброс сетевого стека Windows, который обычно делают при поломке сети, и занимает он секунды. ## 5. Android

### Что уже хорошо
Это стандартный `VpnService` с отдельным процессом под каждый протокол. Работают Always-on VPN и плитка в шторке. При раздельном туннелировании показывается список приложений с иконками и поиском.

### Найденные проблемы
| Проблема | Где | Сложность |

### Улучшения UX на Android
- Отметить уже выбранные приложения, кнопка «показать системные», «выбрать все» и «инвертировать».
- Импорт и экспорт списка пакетов через буфер обмена, как в v2rayNG.
- Наборы приложений («Банки», «Игры»): на Android это аналог папок.
- Менять список при включённом VPN с автоматическим переподключением.
- Подсказать отключить оптимизацию батареи и включить Always-on.

### Сборка под Android
Официальный скрипт работает только на Linux и macOS. На Windows проще всего собирать через **WSL2 (Ubuntu)** или через **GitHub Actions в форке**: в CI upstream используется их собственный runner, его нужно заменить на `ubuntu-latest`. Сложность настройки средняя.

## 6. Что подсмотреть у других клиентов

| Клиент | Что полезно |
|---|---|
| **Mullvad** | Служба с явным автоматом состояний: Подключение → Подключено (только после проверки туннеля) → Ошибка (блокирует трафик). Интерфейс никогда не ждёт службу. Монитор «нет сети» с паузой после пробуждения. Это лучший образец для стабильности. |
| **Proton VPN** | Режимы исключения и включения для приложений и IP. Список программ и ручное добавление EXE. Кнопка «Применить и переподключить». |
| **NordVPN, Windscribe** | В списке выбора показываются **уже запущенные и недавно открытые** приложения. |
| **mihomo (Clash Verge), sing-box** | Правила по процессу: `PROCESS-PATH-WILDCARD`, `process_path_regex`, то есть папки и маски. Работают через TUN, без драйвера. Страница «Соединения» показывает процесс, правило и маршрут для каждого соединения. |
| **Xray-core** | В правилах маршрутизации можно указать процесс по **папке** (путь с `/` на конце). Это пригодится для режима «только эти приложения» в Xray. |
| **v2rayNG** | Выбрать все, инвертировать, поиск, импорт и экспорт списка в буфер. |
| **Hiddify** | Готовые региональные пресеты («обход для России»), автовыбор сервера по задержке. |
| **Throne** | Из живого соединения можно одним кликом создать правило. |

Для пользователей из России особенно полезно: правила по доменам и geoip с автообновлением, например наборы `russia-v2ray-rules-dat`, вместо одноразового перевода доменов в IP. Сейчас Amnezia разрешает домен в IPv4 **один раз** при добавлении, и с CDN это перестаёт работать. Для протоколов семейства Xray это делается сравнительно легко.

## 7. Предлагаемый план работ

**Этап 0. Подготовка (1–3 дня)**
- Форк на GitHub, ветка от `dev`: там уже новый дизайн интерфейса, и выводить свои правки из 5.0.3 нет смысла.
- Собрать Windows-версию локально (`deploy\build.bat`, Qt 6.10, MSVC 2022, Conan).
- Собрать Android через GitHub Actions или WSL2.

**Этап 1. Быстрые победы по стабильности (около 1 недели)**
- Windows: убрать `resetIpStack`, добавить таймаут подключения, показывать ошибки, убрать задержки `Sleep(1000)`, исправить гонку `lastError`, обновлять IP для драйвера при смене сети.
- Забрать из upstream open PR: #3344 и #3099 (утечка и зависание драйвера), #3114 (большие списки маршрутов), #3313 (зависание переподключения), #2431 (блокировки интерфейса).
- Android: флаги `or`, ловить `NameNotFoundException`, убрать ложное «Отключено» при сворачивании, передавать ошибки в интерфейс, кэшировать Prefs, таймаут рукопожатия.

**Этап 2. Удобное раздельное туннелирование (1–2 недели)**
- Windows: правила-папки, выбор из запущенных процессов и установленных программ (Steam/Epic) с иконками, полный путь в списке, подсказка «исключите лаунчер».
- Android: доработать список (отмеченные приложения, системные, массовые действия, асинхронные иконки), импорт и экспорт.
- Обе платформы: менять список без ручного переподключения.

**Этап 3. Глубже (недели и месяцы, по желанию)**
- Явный автомат состояний подключения, проверка живости туннеля, автопереподключение с backoff.
- Правила по доменам и geoip для Xray. Режим «только эти приложения» для Xray на Windows.
- Страница диагностики: журнал и проверка «через что идёт трафик».

## 8. Как вести форк

- **Синхронизация с upstream.** Upstream выпускает релиз раз в 3–6 недель, в `dev` около 30 коммитов в месяц, недавно был крупный редизайн QML. Держите свои правки небольшими сериями коммитов и раз в месяц делайте merge из `dev`. Больше всего конфликтов будет в QML-страницах и `vpnConnection.cpp`. Код Windows-службы и драйвера меняется редко.
- **Одновременно с официальным клиентом не запустится.** Имена pipe, службы, драйвера, WFP-подслоёв и Android-пакета захардкожены. Либо удалите официальный клиент, либо переименуйте всё. Переименование занимает 1–2 дня, и это **важно сделать сразу для Android**, иначе одно приложение заменит другое.
- **Подпись.** Сам клиент и службу для личного использования подписывать не нужно. Драйвер Mullvad берётся готовый и уже подписан. **Не трогайте драйвер**, и подпись не понадобится.
- **Amnezia Premium/Free** требует ключ `PROD_AGW_PUBLIC_KEY` при сборке. Self-hosted серверы и импортированные `.conf`/`vpn://` работают и без него.
- **Лицензия GPLv3.** Для себя можно менять как угодно. Если будете раздавать сборки, нужно открыть исходники, а публичный форк на GitHub это и так обеспечивает.

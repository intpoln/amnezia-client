# Тестирование

## Главное ограничение
На основном ПК пользователя постоянно работает **официальный AmneziaVPN**. У сборки форка те же имена:
- канала `\\.\pipe\amneziavpn`,
- узла QtRO `AmneziaVpnIpcInterface`,
- служб `AmneziaVPN-service`, `AmneziaWGTunnel$AmneziaVPN`, `AmneziaVPNSplitTunnel`,
- устройства драйвера `\\.\MULLVADSPLITTUNNEL`.

Поэтому **на основном ПК нельзя**:
- запускать собранный `AmneziaVPN.exe`: он подключится к службе официального клиента;
- устанавливать или регистрировать собранную службу либо драйвер;
- подключать VPN, менять маршруты, DNS и правила firewall.

**Можно:** собирать проект и запускать unit-тесты (`ctest`), если тест не обращается к службе.

## Уровни проверки

### 1. Unit-тесты (агент, на основном ПК или в CI)
```bash
ctest --test-dir build/client/tests -C Release -R "<TestName>" --output-on-failure
```
- Для этой работы важны тесты `UiAppSTModelAndControllerTest` (`client/tests/testUiAppSTModelAndController.cpp`), `SettingsSignalsTest` и `BackupExportImportTest`. Последнему нужен секретный файл бэкапа, без него тест пропускаем.
- Тесты, которым нужны секреты (`THIRD_PARTY_*`, `AMNEZIA_TEST_API_KEY`) или реальный VPN, в форке не запускаем.
- Новую логику (сканер папок, миграцию настроек) покрываем новыми тестами в `client/tests/`.

### 2. Виртуальная машина (пользователь)
1. Hyper-V или VirtualBox, гостевая Windows 11. Включает пользователь, агенты системные настройки не меняют.
2. Скачать установщик из GitHub Actions: запуск `fork-windows` → Artifacts → `AmneziaVPN_*_windows_x64.exe`.
3. Установить в ВМ, импортировать `.conf` той локации Premium, которая **не используется** на основном ПК в этот момент.
4. Пройти чек-лист нужной задачи (ниже).
5. Если что-то не так, приложить логи. Их можно экспортировать в настройках клиента (раздел журналов): там лог клиента в AppData пользователя и лог службы в ProgramData. Точные пути заданы в `common/logger/logger.cpp`.

### 3. Без ВМ
Пользователь сам ставит сборку вместо официального клиента. Перед этим он сохраняет конфиги, потом при необходимости возвращает официальный клиент.

## Чек-листы

### Исключение папок
- [ ] Добавить папку с игрой или программой. В списке одна строка с путём и числом найденных `.exe`.
- [ ] Подключиться. Программа из папки показывает реальный IP (например, на 2ip.ru через её встроенный браузер, или по счётчику трафика в AppNetworkCounter), а браузер вне папки показывает IP VPN.
- [ ] Добавить в папку новый `.exe` (скопировать любую утилиту), переподключиться: он тоже идёт мимо VPN.
- [ ] Удалить папку из списка, переподключиться: программа снова идёт через VPN.
- [ ] Выбрать очень большую папку (например, `C:\Program Files`): появляется предупреждение, интерфейс не зависает.
- [ ] Старые записи с отдельными `.exe` после обновления на месте и работают.

### Стабильность
- [ ] Подключение и отключение 10 раз подряд: без зависаний, состояние в интерфейсе соответствует реальному.
- [ ] Недоступный сервер (неверный IP в конфиге): через 30–45 с ошибка, а не бесконечное «Подключение…».
- [ ] Сон и пробуждение при подключённом VPN: соединение восстанавливается.
- [ ] Wi-Fi и кабель одновременно: исключения работают.
- [ ] В логе видны времена этапов подключения.

# Решения

Формат: дата, решение, почему, что из этого следует. Новые записи добавляются в конец.

## 2026-10-30. Только Windows, Android отложен
- **Почему:** приоритет пользователя.
- **Следствие:** `client/android/` и Android-ветки кода не трогаем. Если общая правка задевает Android-путь, он должен работать как раньше.

## 2026-10-30. Только режим исключений, режим «только через VPN» не делаем
- **Почему:** пользователю хватает исключений. Режим включения для AmneziaWG требует другого драйвера.
- **Следствие:** работаем только с `AppsRouteMode::VpnAllExceptApps`.

## 2026-10-30. Папки разворачиваем в список .exe, драйвер не трогаем
- **Почему:** драйвер Mullvad (`mullvad-split-tunnel.sys`) принимает только полные пути к образам процессов, папок и масок в нём нет. Изменённый драйвер пришлось бы подписывать у Microsoft (EV-сертификат), а test-signing ломает античиты.
- **Как:** правило-папка хранится как папка. При каждом подключении клиент в фоне рекурсивно ищет `*.exe` и передаёт службе обычный список путей.
- **Следствие:** новый `.exe` подхватится при следующем подключении. Применение на лету возможно позже, через новый IPC-метод.

## 2026-10-30. DLL в список не добавляем
- **Почему:** драйвер определяет процесс по образу `.exe`. Сетевые вызовы из DLL принадлежат процессу, который её загрузил. Процесса с образом `.dll` не бывает.
- **Следствие:** при сканировании папки ищем только `*.exe`.

## 2026-10-30. Premium через экспортированные `.conf`
- **Почему:** для работы подписки в клиенте нужен `PROD_AGW_PUBLIC_KEY`, его выдаёт только Amnezia. Встраивать его из официальной сборки не будем.
- **Следствие:** пользователь выгружает файлы локаций в официальном клиенте и импортирует их как Native-конфигурации AmneziaWG.

## 2026-10-30. Без ВМ: пользователь проверяет сам, заменяя официальный клиент
- **Почему:** так решил пользователь.
- **Следствие:** агенты только собирают и запускают unit-тесты. Для ручной проверки готовят установщик и чек-лист из [TESTING.md](TESTING.md).

## 2026-10-30. Настройки остаются совместимыми с официальным клиентом
- **Почему:** форк и официальный клиент читают одни и те же настройки в реестре (HKCU), а пользователь переключается между ними.
- **Следствие:** новые данные (правила-папки и прочее) храним в **новых ключах**. Формат существующих ключей, например `Conf/ExceptApps`, не меняем. Официальный клиент новые ключи просто не видит.

## 2026-10-30. Инструменты сборки в рабочей папке, а не в системе
- **Почему:** пользователь попросил не засорять систему.
- **Следствие:** Python venv (Conan, CMake, Ninja, aqtinstall), Qt 6.10.1, Qt IFW и кэш Conan (`CONAN_HOME`) лежат в папке `tools/` рядом с репозиторием. Сборка запускается через `fork/scripts/local-build.bat`. WiX локально не ставится, `.msi` собирается только в CI.

## 2026-10-30. Стиль кода как в upstream
- **Почему:** чтобы merge из upstream проходил без лишних конфликтов, а правки при желании можно было предложить upstream.
- **Следствие:** соблюдаем правила из `AGENTS.md` (без комментариев в коде, DRY, компоненты Controls2/Components, переводы через `qsTr`). Изменения держим небольшими. Своё по возможности кладём в новые файлы, а не переписываем чужие.

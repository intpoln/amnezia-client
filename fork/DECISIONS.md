# Решения

Формат: дата, решение, почему, что из этого следует. Новые записи добавляются в конец.

## 2026-10-30. Только Windows, Android отложен
- **Почему:** приоритет пользователя.
- **Следствие:** `client/android/` и Android-ветки кода не трогаем. Если общая правка задевает Android-путь, он должен работать как раньше.

## 2026-10-30. Только режим исключений, режим «только через VPN» не делаем
- **Почему:** пользователю хватает исключений. Режим включения для AmneziaWG требует другого драйвера.
- **Следствие:** работаем только с `AppsRouteMode::VpnAllExceptApps`.

## 2026-10-30. Папки разворачиваем в список .exe, драйвер не трогаем
- **Почему:** драйвер Mullvad (`mullvad-split-tunnel.sys`) принимает только полные пути к образам процессов, папок и масок в нём нет. Изменённый драйвер пришлось бы подписывать у Microsoft (EV-сертификат), а test-signing ломает античиты.
- **Как:** правило-папка хранится как папка. При каждом подключении клиент в фоне рекурсивно ищет `*.exe` и передаёт службе обычный список путей.
- **Следствие:** новый `.exe` подхватится при следующем подключении. Применение на лету возможно позже, через новый IPC-метод.

## 2026-10-30. DLL в список не добавляем
- **Почему:** драйвер определяет процесс по образу `.exe`. Сетевые вызовы из DLL принадлежат процессу, который её загрузил. Процесса с образом `.dll` не бывает.
- **Следствие:** при сканировании папки ищем только `*.exe`.

## 2026-10-31. Ключ шлюза Premium берём из официальной сборки
- **Почему:** без `PROD_AGW_PUBLIC_KEY` подписка в форке не работает. Обновлять конфиги экспортом `.conf` пришлось бы, каждый раз переставляя официальный клиент. Ключ публичный и и так лежит в каждой официальной сборке. Решение пользователя, заменяет решение от 2026-10-30 про экспорт `.conf`.
- **Как:** ключ и списки S3 (`PROD_S3_ENDPOINT`, `FALLBACK_S3_ENDPOINT`) извлечены из официального `AmneziaVPN.exe`. Локально лежат в `tools/agw/gateway-env.bat` вне репозитория, в CI задаются через secrets. В git их нет.
- **Следствие:** Premium в форке работает напрямую. Если Amnezia сменит ключ, его надо заново извлечь из новой официальной сборки (см. [NOTES.md](NOTES.md#ключ-шлюза-premium)).

## 2026-10-30. Без ВМ: пользователь проверяет сам, заменяя официальный клиент
- **Почему:** так решил пользователь.
- **Следствие:** агенты только собирают и запускают unit-тесты. Для ручной проверки готовят установщик и чек-лист из [TESTING.md](TESTING.md).

## 2026-10-30. Настройки остаются совместимыми с официальным клиентом
- **Почему:** форк и официальный клиент читают одни и те же настройки в реестре (HKCU), а пользователь переключается между ними.
- **Следствие:** новые данные (правила-папки и прочее) храним в **новых ключах**. Формат существующих ключей, например `Conf/ExceptApps`, не меняем. Официальный клиент новые ключи просто не видит.

## 2026-10-30. Инструменты сборки в рабочей папке, а не в системе
- **Почему:** пользователь попросил не засорять систему.
- **Следствие:** Python venv (Conan, CMake, Ninja, aqtinstall), Qt 6.10.1, Qt IFW и кэш Conan (`CONAN_HOME`) лежат в папке `tools/` рядом с репозиторием. Сборка запускается через `fork/scripts/local-build.bat`. WiX локально не ставится, `.msi` собирается только в CI.

## 2026-10-30. Стиль кода как в upstream
- **Почему:** чтобы merge из upstream проходил без лишних конфликтов, а правки при желании можно было предложить upstream.
- **Следствие:** соблюдаем правила из `AGENTS.md` (без комментариев в коде, DRY, компоненты Controls2/Components, переводы через `qsTr`). Изменения держим небольшими. Своё по возможности кладём в новые файлы, а не переписываем чужие.

## 2026-10-31. Сброс сетевого стека при подключении убран
- **Почему:** на каждом подключении служба выполняла `netsh int ip reset` и `netsh winsock reset`. Это медленно, сбрасывает настройки адаптеров пользователя и требует перезагрузки, чтобы полностью сработать.
- **Следствие:** IPC-метод `resetIpStack` удалён из клиента и службы. `flushDns` запускается без ожидания (`ipconfig /flushdns` через `QProcess::startDetached`).

## 2026-10-31. Таймаут подключения 40 с в VpnConnection
- **Почему:** зависшее подключение висело в «Подключение…» бесконечно. Таймер в `VpnConnection`, а не в протоколе: протокол уходит в Disconnected посреди переподключения, а отключение пользователем должно таймер гасить.
- **Следствие:** Connecting и Reconnecting дольше 40 с заканчиваются ошибкой `ConnectionTimeoutError`. Значение в `connectionTimeoutMsec` (`vpnConnection.cpp`).

## 2026-10-31. Свои коды ошибок с 750
- **Почему:** upstream занимает 700–703 и может добавлять новые подряд. Отдельный диапазон не даёт кодам совпасть после merge.
- **Следствие:** новые ошибки форка добавляем с 750 дальше.

## 2026-10-31. Из PR upstream #3313 берём только часть
- **Почему:** PR делает то же, что наши 2.2–2.6 (таймаут, ошибки службы, асинхронные вызовы, `Qt::UniqueConnection`), но по-другому: свой таймаут 30 с внутри `LocalSocketController` и код ошибки 704. Целиком он конфликтует с нашими правками.
- **Как:** взяты части, которых у нас нет: отключение туннеля при остановке службы (`LocalServer::shutdown`, `NeedsStopOnShutdown`), обмен со службой туннеля по каналу с общим таймаутом 5 с (`windowstunnelpipe.h`), проверка ответа `errno=0` в `updatePeer`/`deletePeer` и мелкие исправления (двойное удаление `m_logworker`, остановка таймера рукопожатия). Переделку очереди активаций в `LocalSocketController` и тесты из PR не брали.
- **Следствие:** при следующем merge upstream, если PR примут, конфликты в этих файлах разрешать в пользу upstream там, где он делает то же.

## 2026-10-31. PR upstream #2431 не берём
- **Почему:** сделан на старой структуре файлов (`client/protocols/`, `client/vpnconnection.cpp`) и добавляет индикатор скорости, которого пользователь не просил. Перенос UI-блокировок закрыт нашим 2.8.

## 2026-10-31. Ошибка исключений приложений не отключает VPN
- **Почему:** решение пользователя. Защищённое подключение важнее исключений, а пользователь должен понять, что исключения не работают и что делать.
- **Как:** служба останавливает драйвер раздельного туннелирования и шлёт `backendFailure`, туннель остаётся. Клиент показывает окно с причиной, вариантами исправления и кнопкой «Переподключить». Код ошибки 752 больше не нужен и удалён. Остальные ошибки службы WG/AWG ставят Error (`TunnelError`).
- **Следствие:** все приложения, включая исключённые, идут через VPN до переподключения.

## 2026-10-31. Своя метка маршрутов исключений 0x5e7f
- **Почему:** PR #3114 при старте службы удаляет маршруты с меткой исключений, оставшиеся после сбоя. Метку `0x5e72` используют Mozilla VPN и официальный клиент, очистка могла удалить их маршруты.
- **Следствие:** маршруты форка с меткой `0x5e72`, оставшиеся до этого изменения, очистка больше не удаляет; они пропадают после перезагрузки.

## 2026-10-31. Что из ревью Codex не исправляем
- **Второе ревью, не исправляем:** пропуск чужого изменения маршрута во время пересчёта в `WindowsRouteMonitor::routeChanged()` и поясняющие комментарии в `daemon.cpp` и `wireguardutils.h`. Это код upstream PR #3114 без изменений: окно узкое, правка рискует вернуть шторм маршрутов, удаление комментариев добавит конфликтов при слиянии. Синхронное сканирование больших папок и запоздалое «Папка добавлена» остаются в 1.5b.
- **Решение пользователя:** вложенные ожидания и таймаут Xray, ошибки split tunnel для OpenVPN/Xray только в логе, uplink через vEthernet Hyper-V, смена uplink только по метрике, `PBT_APMRESUMEAUTOMATIC`, IPv6 в наблюдателе сети, утечка наблюдателя IPC, возможное двойное переподключение после сна.
